# SIQS Design — Self-Initializing Quadratic Sieve

## Scope

SIQS (Contini 1997) factors composites in the 25-100 digit range with complexity
`L_N(1/2, 1)`. In this codebase it serves two roles:

1. **Fast path for 100 ≤ bit_count(N) ≤ 180**, where GNFS overhead dominates
2. **Probe before GNFS** for N up to 100 digits, so unfortunate GNFS polynomial
   selections never block easy factorizations

The header `include/gnfs/siqs/siqs.hpp` carries the full implementation
(roughly 1670 LOC) and is intentionally header-only so the pipeline can inline
small primitives such as `mod_mul32` / `tonelli_shanks` without an LTO pass.

## Pipeline Position

```
select_method (src/api/pipeline.cpp)
  ≤6d  / ≤20bit   → TrialDivision
  ≤24d / ≤80bit   → PollardRho
  ≤100d           → SIQS    (probe; SIQS fallback to GNFS on failure)
   >100d          → GNFS    (with SIQS probe if ≤100d)
```

ENV overrides intercept the router:

- `GNFS_FORCE_SIQS=1` jumps directly to SIQS for any N above 6 digits
- `GNFS_DISABLE_SIQS=1` skips the SIQS phase (both router and GNFS probe)

Manual `Config::method` always wins over ENV.

## Algorithm Outline

The polynomial family is `Q_a(x) = (A·x + B)^2 - N`, with

- `A` a product of `s` factor base primes chosen so that `A ≈ sqrt(2N) / M`
- `B` a square root of N modulo A, computed via CRT over the prime factors of A
- Self-initialization (Contini): given one base `B`, the remaining `2^(s-1) - 1`
  values are generated by Gray-code bit flips, each one a single subtract from
  the precomputed sieve offsets

For every polynomial we sieve `x ∈ [-M, M]`, accumulating `log(p)` in a byte
array at all positions where `p` divides `Q_a(x)`. Positions whose accumulated
log clears the threshold proceed to trial division against the full factor base
plus an optional one- or two-large-prime check.

Smooth and partial relations feed a GF(2) matrix whose left null space supplies
congruences `X² ≡ Y² (mod N)`, after which `gcd(X ± Y, N)` recovers a factor.

## Parameter Calibration

The `select_params` table is tuned against msieve, CADO-NFS, and YAFU defaults.
The crucial knobs by digit band:

- `fb_size` — primary factor base length (excluding the `p=2` sentinel)
- `sieve_half` — `M`, the half-width of the sieve interval
- `lp_multiplier` — large prime bound is `fb.back().p * multiplier`
- `num_a_factors` — `s`, the number of primes composing each `A`. Maximum 12
  in the current table; `MAX_A_FACTORS = 16` in `init_poly` leaves headroom
- `sieve_error` — slack absorbed by log approximation plus prime powers
- `small_prime_cutoff` — primes below this are skipped during sieving and
  paid back via `small_contrib` in the threshold computation

Two-large-prime support is implemented end-to-end but currently disabled by
setting `lp_bound_sq = 0`. The reason is documented inline near `siqs.hpp:1450`:
2LP cycle extraction failed for certain multipliers in earlier runs, and 1LP
merging already supplies enough usable relations. Re-enabling requires a
re-validation across the 50-90 digit band.

## Performance Notes

Observed on Apple M5 (10 P+E cores), Debug build:

| N (bits / digits) | SIQS factor time | GNFS path overhead | Ratio |
|-------------------|-----------------:|-------------------:|------:|
| 101 / 31          |            11 ms |          seconds   | 100×+ |
| 181 / 55          |           ~3.1 s |          minutes   |  20×+ |

(180-bit measurement includes 79 K polynomials and 1.86 K usable relations.)
GNFS dominates only above ~100 digits, where `L_N(1/3, c)` finally outweighs
SIQS's `L_N(1/2, 1)`.

## Known Limitations

- **2LP cofactor handling is gated off** (`lp_bound_sq = 0`); single-LP graph
  merging is the production path
- **Beyond ~57 digits, extraction failures dominate** in current calibration.
  The 60-digit band needs FB and threshold tuning before being declared
  production-ready. Use GNFS for ≥60 digits until then
- **No checkpointing**: each SIQS run starts from scratch. Acceptable since the
  whole algorithm completes inside the GNFS Phase 2 budget
- **Single multiplier per run**: `select_multiplier` runs once on input N; for
  unlucky N where the Knuth-Schroeppel score is misleading, the only recourse
  today is to let SIQS fail and fall through to GNFS
